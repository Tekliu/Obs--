 ## 流式多处理器（SM，Streaming Multiprocessor） 
是 GPU 里真正干活的核心计算单元。可以把它理解为 GPU 的"心脏"或"车间"。

把整个 GPU 想象成一个大型工厂：

- GPU 芯片 = 整个工厂
- SM = 工厂里的一个个独立车间
- CUDA Core = 车间里的工人  

每个**SM 都是一个能独立执行任务的微型处理器**。

#SM里面有什么

每个 SM 内部包含：

| 部件                 | 作用                           |
| ------------------ | ---------------------------- |
| [[CUDA Core]]      | 做整数/浮点运算（加减乘除）               |
| [[Tensor Core]]    | 做矩阵乘法（AI 专用）                 |
| [[Warp Scheduler]] | 负责从 warp 里挑一个喂给 CUDA Core    |
| Register File      | 超高速临时存储（每个 thread 私有）        |
| Shared Memory      | 同一 block 的 thread 共享的小仓库     |
| L1 Cache           | 缓存从显存取来的数据和 Shared Memory 共用 |


#SM怎么干活

前面讲过，block 被分配到 SM 上执行。一个 SM 可以同时接多个 block（取决于资源够不够）。具体流程：

SM 接到 block
  └─ 把 block 里的 thread 分成 warp（32 个一组）
      └─ Warp Scheduler 每周期挑一个 warp
          └─ 把这个 warp 的 32 个 thread 喂给 CUDA Core
              └─ 32 个 thread 同时算，只是数据不同

关键：一个 SM 里的 warp scheduler 是交替执行 warp 的——当一个 warp 在等数据（比如从显存读），scheduler 立刻切到另一个 warp 去算，用计算掩盖延迟。这是 GPU 高效的核心秘密。

SM 和之前概念的关系

一次 kernel launch
  └─ Grid（整个任务）
      └─ Block（任务的分组）
          └─ 被分配到某个 SM 上
              └─ 拆成 Warp（32 thread 一组）
                  └─ Warp Scheduler 调度
                      └─ 喂给 CUDA Core 执行

为什么叫"流式多处理器"

"流式"（Streaming）是因为 GPU 的处理模式是流水线式的——数据像水流一样持续涌入，SM 不断从 warp 池里捞活干，不等待、不阻塞。"多处理器"（Multiprocessor）是因为每个 SM 本身就是一个能独立执行指令的处理器，多个 SM 并行工作。

一句话总结：SM 是 GPU 里的独立计算车间，每个车间有自己的工人（CUDA Core）、调度员（Warp Scheduler）和小仓库（Shared Memory），block 被分到 SM 上执行，SM 再把 block 里的 thread 拆成 warp 喂给 CUDA Core 算。
