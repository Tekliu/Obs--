分支预测（Branch Prediction）= CPU 遇到 
"if/else"、循环这种"条件跳转"时，不等条件算完，先猜一个方向继续取指执行的技术。猜对了 → 流水线不停，白赚；猜错了 → 把猜错的指令全扔掉，回到正确路径重来，罚 10-20 个时钟周期。

IF → ID → EX → MEM → WB

问题出在条件分支指令（"if/else"、循环）：

  cmp  eax, 0
  je   target     ; 如果 eax == 0 跳转到 target，否则顺序执行下一条
  mov  ebx, 1     ; 不跳时执行这里
target:
  mov  ecx, 2     ; 跳时执行这里

CPU 在 IF 阶段取回 
"je target"，但到底跳不跳，要等到 EX 阶段才算出来（cmp 的结果在 EX 才算完）。
如果是 5 级流水线 → 等 2 级才知道跳不跳
如果是现代 14-19 级深流水线 → 等 12-15 级才知道

不预测的死法：
IF(ID EX MEM WB) → 干等 12-15 个周期 → 知道跳不跳 → 才开始取正确路径的下一条
                    ↑ 流水线全空转，IPC 从 4 暴跌到 <1

程序里平均每 5-7 条指令就有 1 条是分支（占比 15-20%）——如果每遇分支都空等 15 周期，整个流水线优势全毁。

所以 CPU 的选择只有两个：

- A. 死等（安全但慢，吞吐量崩盘）
- B. 猜一个方向，提前取指执行（快但偶尔错）

现代 CPU 全选 B——每个分支都猜。

猜的机制（两层猜测）
分支预测其实要猜两件事：

猜什么 谁负责 怎么猜
跳不跳（方向） BHT 分支历史表 看这条分支过去的行为
跳哪里（目标地址） BTB 分支目标缓冲 记这条分支上次跳到的地址

1️⃣ 静态预测（早期 CPU / 无历史时）
固定规则，不看历史：
- 总是预测不跳转：对 "if" 准确率 ~50%
- 向后跳转预测跳、向前跳转预测不跳（[[BTFNT 规则]]）：
- 向后跳 = 循环回退（"for/while" 的末尾跳回开头）→ 大概率继续循环 → 预测"跳"
- 向前跳 = "if" 成立时跳过一段 → 大概率不成立 → 预测"不跳"
- 这条规则不用记历史就能达到 ~65% 准确率
2️⃣ 动态预测（现代 CPU 主力）
记历史，2-bit 饱和计数器是最常见的入门版：
每个分支指令地址 → 对应一个 2-bit 计数器
11: 强跳转（预测 taken）
10: 弱跳转（预测 taken）
01: 弱不跳（预测 not taken）
00: 强不跳（预测 not taken）
分支实际 taken  → 计数器 +1（饱和在 11）
分支实际 not taken → 计数器 -1（饱和在 00）

典型循环 
"for i in 1..100" 的表现：

分支结果序列：  T T T T T ... T T N   （前 99 次跳，最后 1 次不跳）
2-bit 计数器： 10→11→11→...→11→10→01
准确率：99/100 = 99%

只有循环退出那一次猜错 → 动态预测对循环近乎完美。
现代 CPU 用更复杂的 TAGE 预测器（多历史长度组合），真实负载下准确率 97-99%。
## 猜错的成本——为什么"赌"是值得的

预测对的代价：0 周期（流水线不停）
预测错的代价：冲刷流水线（flush）+ 从正确路径重取指，10-20 周期浪费
算笔账（现代 14 级流水线，分支占比 15%）：

不预测：每个分支等 14 周期 → 平均每条指令浪费 0.15 × 14 = 2.1 周期
预测准确率 98%：0.15 × 0.02 × 14 = 0.042 周期/指令
                        ↓
              比不预测少了 50 倍的浪费！
所以哪怕猜错，只要准确率 > 90%，整体还是赚翻——这就是为什么现代 CPU 愿意花大量晶体管做复杂的预测器。

跟"推测执行"是一对双胞胎

光预测不执行没用，所以 CPU 配套做了推测执行（Speculative Execution）：

Cycle 1: IF 取回 `je target`，预测"跳"
Cycle 2: 沿预测路径（target 方向）继续 IF/ID
Cycle 3: 取 target 后的指令，开始 EX
...
Cycle N: `je` 到 EX 阶段，条件算完 → 实际确实要跳 ✅
         → 推测执行的指令全部"提交"（commit），流水线零中断

或者：
Cycle N: 条件算完 → 实际不跳 ❌
         → 把推测执行的指令全部丢弃（flush）
         → 从正确路径（不跳的方向）重新 IF
         → 罚 10-20 周期

⚠️ 2018 年的 Spectre/Meltdown 漏洞就是钻了这个空子：CPU 猜错时虽然丢弃了执行结果，但缓存状态已经变了——攻击者通过测缓存访问时间，能推断出"本不该访问的秘密数据"。这是分支预测"推测执行"黑暗面的一次曝光。
一句收

分支预测 = CPU 遇到 
"if/else"/循环时，不等条件算完，先猜"跳/不跳"+“跳哪里”，按猜测路径继续取指执行；猜对 0 代价，猜错冲刷流水线罚 10-20 周期。现代 CPU 靠动态预测器（BHT 2-bit 计数器 → TAGE）做到 97-99% 准确率，这是深流水线能跑满 IPC 的关键——没有它，每遇分支空等十几周期，吞吐量崩盘。
接你前面那条线完整闭环：

取指（IF） → 译码（ID） → 执行（EX） → 访存（MEM） → 写回（WB）
   ↑                              ↑
   │                              │
   └─ 分支预测在这猜方向            └─ 这里才算出实际跳不跳
      + BTB 猜目标地址
      
猜对：流水线不停，IPC 维持高位
猜错：flush 流水线，罚 10-20 周期，重新取正确路径
