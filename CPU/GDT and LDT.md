GDT 和 LDT 是 x86 保护模式下管"分段"的俩表——上一轮说到 
"CS:IP" 在保护模式里 CS 不是段基址了，是**选择子**（Selector），这个选择子就是去查 GDT/LDT 的。

### 先解决"为啥要有这俩"

实模式下：
"CS × 16 + IP = 物理地址"，CS 随便写，任何程序都能跳去改别家内存——没隔离、没权限，病毒狂喜。

保护模式想解决三件事：

1. 基址/限长：这段内存从哪开始、多长，越界就 #GP 异常
2. 权限：你是 Ring 0（内核）还是 Ring 3（用户），不能乱跳
3. 类型：代码段 / 数据段 / 栈段 / TSS / 门，各管各的

这三样塞不进 16 位 CS 里，于是抽出来放一张表里——这就是 段描述符（Segment Descriptor），8 字节一条。

💡 **现代 OS（Linux/Windows/macOS）基本不用 LDT**——**分段这活被分页（paging，CR3 那层）** 完全替掉了，所以 LDT 在课本里有、实战里几乎空着。GDT 还在用，但一般只挂 4-5 条：内核 code、内核 data、用户 code、用户 data、[[TSS]]，每段 base=0、limit=4G（叫"平坦模式 flat model"），等于"分段存在但躺平，全靠分页干活"。

选择子（Selector）长啥样——接你上一轮 CS

**CS/DS/SS/ES/FS/GS 在保护模式里存的不是基址**，是16 位选择子：

 15    3  2   1  0
[ 索引 ] [TI]  [RPL] 

- bit 3-15（高 13 位）：GDT/LDT 里的第几条描述符（0-based）
- bit 2（TI）：0=查 GDT，1=查 LDT
- bit 0-1（RPL）：请求权限级（Ring 0-3，配合描述符里的 DPL 做权限检查）

例子：CS = 
"0x08"

- 二进制：
"0000 0000 0000 1000" → 索引=1，TI=0（查 GDT），RPL=0
- 去 GDT 第 1 条（第 0 条是 NULL 占位）拿出代码段描述符 → 基址 + IP = 线性地址

描述符（Descriptor）8 字节里藏啥（简化版）

┌────────────────────────────────────┐
│ 基址(31:24) │ G │ D │ 限长(19:16) │  ← 高 4 字节
│ DPL │ P │ S │ TYPE │ A │ 基址(23:16) │
├────────────────────────────────────┤
│ 基址(15:0)      │    限长(15:0)     │  ← 低 4 字节
└────────────────────────────────────┘

关键字段：

- 基址 Base：32 位，段从哪开始
- 限长 Limit：20 位，段多长（G 位=1 时 ×4K，所以最大 4G）
- DPL：描述符权限级（0=内核，3=用户）
- TYPE：代码/数据/可读可写可执行……
- S=1 是普通段，S=0 是系统段（TSS/门）

算线性地址时：CS 选择子 → GDT[索引] → 拿出 Base → Base + IP = 线性地址 → 再走分页（CR3）→ 物理地址

现代 Linux 平坦模式下 Base=0，所以"线性地址 = IP"——分段那层其实没干活，全靠 CR3 分页那层隔离进程。GDT 存在的意义更多是兼容 x86 规范 + 给 TSS/CS 权限跳（syscall/iret）用。

一句收

GDT = 全局段描述符表，一份，GDTR 指；LDT = 每任务局部段表，LDTR 指，现代 OS 基本废弃；CS/DS 这些段寄存器在保护模式里存的是"选择子"，去 GDT/LDT 查描述符拿 Base+Limit+DPL，再 +IP 得线性地址，再走 CR3 分页到物理地址。
