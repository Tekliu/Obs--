冷启动和热重启的区别，本质上是**"断电/上电" vs "不断电/复位"**​ 的差异。结合你前面学的 UEFI 七阶段，它们的区别主要体现在**从哪里开始跑、内存状态是否保留、固件走哪条路径**。

## 一句话定位

> **冷启动（Cold Boot / Cold Start）= 系统从完全断电状态上电**，所有硬件回到初始态、内存清空、固件从 SEC 阶段开始完整跑七阶段。
> 
> **热重启（Warm Reboot / Soft Reset）= 系统在不断电的情况下通过复位信号重启**，固件可能跳过部分早期初始化、走较短路径。

## 核心区别对照表

| 维度             | 冷启动（Cold Boot）                         | 热重启（Warm Reboot）                                           |
| -------------- | -------------------------------------- | ---------------------------------------------------------- |
| **电源状态**​      | 完全断电 → 上电（ATX 电源从 0V → 12V/5V/3.3V）    | 电源保持供电，只触发复位信号（RESET# 引脚）                                  |
| **CPU 状态**​    | 从 Reset Vector 开始（x86: `0xFFFFFFF0`）   | 同上，但部分 [[MSR]]/微码状态可能保留                                    |
| **内存（DRAM）**​  | 完全清空，需重新训练（PEI 阶段 Memory Init PEIM）    | 内容可能还在，但 OS 视为"脏" → 重新初始化                                  |
| **固件路径**​      | SEC → PEI → DXE → BDS → TSL → RT 完整七阶段 | 通常也是 SEC → PEI → DXE → ... 但 **PEI 可走快捷路径**                |
| **Boot Mode**​ | `BOOT_WITH_FULL_CONFIGURATION`（完整配置）   | `BOOT_WITH_MINIMAL_CONFIGURATION` 或 `BOOT_ON_FLASH_UPDATE` |
| **耗时**​        | 较长（POST + DRAM 训练 + 设备枚举，通常 5-30 秒）    | 较短（跳过部分硬件重检，通常 2-10 秒）                                     |
| **典型触发**​      | 按电源键开机、从 S5 软关机状态上电                    | `reboot` 命令、`Ctrl+Alt+Del`、看门狗超时、Triple Fault、Reset 按钮     |
| **硬件重置范围**​    | 全部硬件（包括 BMC/ME/PSP 等带外管理器）             | 仅 CPU/北桥/主内存，带外管理器可能不重置                                    |

## 在 UEFI 七阶段里的具体差异

### 冷启动的完整路径

```
ATX 电源上电 → 12V/5V/3.3V 建立 → VRM 输出 Vcore
  ↓
CPU Reset → Reset Vector (0xFFFFFFF0)
  ↓
SEC:  Cache-as-RAM 建临时栈、信任根验证
  ↓
PEI:  ★完整 DRAM 训练★（时序校准、电平匹配、DQS 训练）
      构建 HOB 列表
  ↓
DXE:  完整驱动派遣、PCI 枚举、ACPI 表构建
  ↓
BDS:  读 NVRAM BootOrder → 加载 OS Loader
  ↓
TSL:  OS Loader 执行
  ↓
RT:   ExitBootServices → OS 接管
```

冷启动的 PEI 阶段必须**完整跑 DRAM 训练**——因为断电后内存颗粒里的电荷全放掉了，内存控制器必须重新学"怎么跟这些 DRAM 颗粒说话"（时序、电压、阻抗匹配）。

### 热重启的路径

```
OS 调用 ResetSystem() / 看门狗超时 / Reset 按钮
  ↓
CPU 收到 RESET# 信号 → 回到 Reset Vector
  ↓
SEC:  Cache-as-RAM 建临时栈（同冷启动）
  ↓
PEI:  Boot Mode = BOOT_WITH_MINIMAL_CONFIGURATION
       ★DRAM 训练可跳过或简化★（内存内容可能还在）
       构建 HOB 列表
  ↓
DXE:  驱动派遣（部分驱动可走"快速重初始化"路径）
  ↓
BDS:  读 BootOrder → 加载 OS Loader
  ↓
TSL → RT:  OS 接管
```

热重启时 DRAM 可能还保持着带电状态（ATX 电源的 5Vsb 或主 12V 没断），内存颗粒里的电荷没完全流失，所以**内存控制器可以跳过完整的 DRAM 训练**，只做轻量级重新初始化。这就是为什么热重启比冷启动快——省掉了最耗时的 [[DRAM]] 训练步骤（通常 100-500ms）。

## ACPI 规范里的对应状态

ACPI 规范把系统电源状态分了 S0-S5：

| 状态      | 含义                    | 对应启动类型                        |
| ------- | --------------------- | ----------------------------- |
| **S0**​ | 工作状态（Working）         | 已在 RT 阶段                      |
| **S1**​ | 浅睡眠（Power-on Suspend） | 通过 AL 阶段 S1 路径恢复              |
| **S2**​ | 深睡眠                   | 通过 AL 阶段 S2 路径恢复              |
| **S3**​ | 挂起到内存（Sleep/Suspend）  | 通过 AL 阶段 S3 Resume 专用路径       |
| **S4**​ | 挂起到磁盘（Hibernate）      | 通过 AL 阶段 S4 路径，下次启动走冷启动+从磁盘恢复 |
| **S5**​ | 软关机（Soft Off）         | **冷启动**（下次上电）                 |
| **G3**​ | 机械断电（Mechanical Off）  | **冷启动**（下次上电）                 |

**所以**：

- 从 **S5/G3**​ 上电 = **冷启动**
    
- 从 **S3/S4**​ 唤醒 = 通过 **AL 阶段**​ 走专用恢复路径（不是完整的冷启动，但也不同于热重启）
    
- **热重启**（Warm Reboot）= **不进任何 S 状态**，直接 Reset
    

## 触发热重启的常见方式

```
1. OS 级：reboot 系统调用 → 内核调 Runtime Services 的 ResetSystem()
2. 键盘：Ctrl+Alt+Del（Windows/Linux 控制台）
3. 硬件：Reset 按钮（主板上的 RESET# 引脚触发）
4. 看门狗：UEFI 看门狗或硬件看门狗超时
5. 异常：CPU Triple Fault（GP 嵌套异常处理失败）
6. 固件：固件更新后要求重启
7. 带外：BMC/IPMI 发送重置命令
```

## 嵌入式/ARM 平台的差异

在 ARM/Linux 嵌入式设备上，"冷启动 vs 热重启"的差异更明显：

||冷启动|热重启|
|---|---|---|
|**POR（Power-On Reset）**​|完整上电复位|不涉及|
|**Warm Reset**​|不涉及|SoC 内部 Reset 控制器触发|
|**DRAM**​|必须完整训练|可跳过（内容保留）|
|**BootROM**​|重新执行|重新执行，但可检测"热重启"标志|
|**eMMC/SD**​|重新初始化|可保留状态|

ARM Trusted Firmware (TF-A) 里明确区分：

```
Cold boot:  BL1 → BL2 → BL31 → BL32 → BL33
Warm boot:  通过 PSCI CPU_ON / SYSTEM_RESET → 走较短路径
```

## 一个实战例子：Linux 下的区别

你在 Linux 终端敲：

```bash
# 热重启
$ sudo reboot
→ 内核调 runtime_service → ResetSystem() → CPU Reset → UEFI 重新从 SEC 开始
→ 但 Boot Mode = BOOT_WITH_MINIMAL_CONFIGURATION
→ PEI 跳过 DRAM 训练
→ 启动快

# 冷启动
$ sudo poweroff    # 进 S5
# 然后按电源键
→ ATX 电源断电再上电
→ 完整 UEFI 七阶段
→ PEI 完整 DRAM 训练
→ 启动慢但最干净
```

`dmesg` 里能看到区别：

```
# 热重启
[    0.000000] efi: 重启原因: warm reset

# 冷启动  
[    0.000000] efi: 重启原因: cold reset
```

## 为什么有时候热重启会"卡住"而冷启动不会

这是工程师经常遇到的现象，原因是：

```
热重启时：
  - DRAM 内容可能还在，但处于"脏"状态
  - 某些 PCIe 设备状态机没完全复位
  - 固件走了快捷路径，跳过了某些清理
  → 可能导致设备枚举异常、驱动加载失败

冷启动时：
  - 所有硬件回到上电初始态
  - 固件走完整路径，彻底重新初始化
  → 最干净的状态
```

所以**调试硬件问题时，工程师常说"冷启动试试"**——因为冷启动能清除热重启残留的脏状态。

## 一句收

> **冷启动 = 系统从完全断电状态上电，ATX 电源 0V → 12V，CPU 从 Reset Vector 开始，UEFI 完整跑七阶段（SEC→PEI→DXE→BDS→TSL→RT），PEI 阶段必须完整 DRAM 训练，Boot Mode = BOOT_WITH_FULL_CONFIGURATION，耗时较长（5-30秒），对应 ACPI S5/G3 上电。热重启 = 系统在不断电情况下触发 Reset 信号（reboot 命令/Reset 按钮/看门狗/Ctrl+Alt+Del），电源保持供电，UEFI 同样从 SEC 开始但 PEI 阶段可跳过或简化 DRAM 训练（内存内容可能还在），Boot Mode = BOOT_WITH_MINIMAL_CONFIGURATION，耗时较短（2-10秒）。本质区别：冷启动"彻底重新初始化所有硬件"，热重启"快速复位、尽量复用现有状态"。**

## 接你前面整条线

```
冷启动的完整路径：
  ATX 断电→上电 → Vcore 建立 → CPU Reset → SEC → PEI(完整 DRAM 训练)
  → DXE → BDS → TSL → RT → OS

热重启的路径：
  OS ResetSystem() → CPU Reset → SEC → PEI(简化/跳过 DRAM 训练)
  → DXE(快速重初始化) → BDS → TSL → RT → OS

S3 唤醒的路径（你前面学的 AL 阶段）：
  OS 进 S3 → 通过 AL 阶段 → 专用 S3 Resume 路径
  → SEC → PEI(S3 Resume PEIM) → 直接恢复内存上下文 → 跳回 OS 睡眠点
```

三者对比：

- **冷启动**：最完整、最慢、最干净
    
- **热重启**：中等完整、较快、可能残留脏状态
    
- **S3 唤醒**：最短路径、最快、内存内容完全保留
    

你前面从 "MOS → Vcore → CS:IP → GDT → TSS → SEC → PEI → DXE → BDS → TSL → RT → AL" 一路钻下来，**冷启动/热重启/S3 唤醒是系统"重新开始"的三种不同入口**——它们都从 CPU Reset 开始，但根据 Boot Mode 和硬件状态，走不同的 PEI/DXE 路径，最终都殊途同归到 OS 接管。

要不要顺着把 **"DRAM 训练具体在 PEI 阶段干了啥（时序校准、Write Leveling、DQS 训练、ZQ 校准）"**​ 过一下？那块是把"冷启动为啥比热重启慢 100-500ms"在硬件信号级钉死，接你 Vcore/内存这条线。还是想看 **"Linux 内核的 reboot 系统调用怎么走到 UEFI 的 ResetSystem()，以及不同 reboot 模式（warm/cold/poweroff/hard）的区别"**？后者更接你日常 `sudo reboot` 的直觉，前者更体系结构底层。
