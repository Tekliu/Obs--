⚡ 按开机键之后发生了什么

你按的是机箱上那个开关（其实是发给 [[EC and PCH]]的一个信号），接下来是电源 + 主板芯片组配合的一连串动作，不是"通电就完事"：
1. 待机先活（G3 → S5）
- [[ATX 电源]]接到市电后，先出 +5VSB（Standby，待机 5V），供主板上的 EC / Super I/O / PCH 用
- 这时候主机看起来"关机"，但其实主板上一小块电路一直活着，等开机信号

2. 按开机键 → EC / PCH 拉 
"PS_ON#"

- EC（嵌入式控制器，笔记本一定是它，台式机有的是 PCH 直接管）收到前面板开关的触发
- 拉低 
"PS_ON#" 引脚 → ATX 电源看到这个信号，才开始输出主供电

3. ATX 主电一组组上来

- 
"+3.3V / +5V / +12V" 主轨先后爬升
- 其中 
"+12V" 给 [[VRM]]（电压调节模块，CPU 旁边那堆电感电容） 用，VRM 再降压到 Vcore（CPU 核心电，现在大概 1.0–1.3V 动态）、VDIMM（内存电，1.2V DDR4/5）、VCCIO / VCCSA 等
- 这些电不是同时到的，有严格的 Power Sequence（比如先 VCCSA 再 VDIMM，再 Vcore），顺序错了内存训不出来或者直接保护

4. 
"PWR_OK"（也叫 
"PGOOD"）拉高 ← 这就是"供电稳定"的硬信号

- ATX 电源内部自己监测各组电压，爬坡到位、波纹合格，就拉高 
"PWR_OK" 发给主板
- 主板上的 VRM 也有自己的 
"PGOOD"，各组都 ok 了才汇总发给 PCH
- PCH 收到 
"PWR_OK" 之后，才会释放 
"PLTRST#"（平台复位），进而释放 
"CPURST#"

5. CPU 终于复位，取第一条指令

- 
"CPURST#" 释放 → CPU 的 CS:IP 被硬件强行指向 
"0xFFFFFFF0"
- 那里是 SPI Flash（存 UEFI 固件）的映射窗口 → 开始跑 SEC 阶段

🎯 所以"供电稳定"到底稳了什么

不是"电通了"这么简单，是三层都过了：

层级 谁负责 不稳会怎样
ATX 主电 +5/+12 到位 电源自身 电源风扇转但主板不亮，debug 卡无 code
VRM 降压输出 Vcore/VDIMM/VCCIO… 主板 VR 区 黑屏、反复重启、DRAM LED 常亮

"PWR_OK" → PCH → 
"PLTRST#" 释放 时序链路 卡在"伪开机"状态，风扇转但 CPU 不动

🔧 为什么不能"通电就让 CPU 跑"

电压从 0 爬到额定值要几毫秒，这段时间里：

- 时钟还没锁（晶振起来需要稳定时间）
- 逻辑电平在阈值附近晃，触发器状态不确定
- Vcore 没到额定，CPU 内部门电路驱动不了

如果这时候就把 
"CPURST#" 放掉，CPU 第一条指令都可能译错，直接跑飞。
"PWR_OK" 本质是个"大家都 ready 了"的握手信号，由电源 → 主板 → PCH 一级级确认，最后才给 CPU 开绿灯。

🪛 民间"供电不稳"的症状对应

- 按开机键没反应：90% 是 
"PS_ON#" 没拉出去（开关坏了 / EC 没电 / PCH 条件不满足）
- 风扇转一下停、再转再停循环：
"PWR_OK" 起了又掉，VRM 过流 / 短路保护
- DRAM LED 常亮：Vcore 起来了但 VDIMM 那路 PG 没到，内存训失败
- 能亮但随机死机：不是"启动阶段"的供电问题，是运行中 VRM 扛不住负载 / 电源纹波大

所以启动链那句"按下电源 → 主板供电稳定（PCH/EC 发 POWER_OK）"，准确说是：

按开机键 → EC 拉 
"PS_ON#" → ATX 出主电 → VRM 降出 Vcore/VDIMM… → 各级 
"PGOOD" 汇总 → PCH 收 
"PWR_OK" → 释放 
"PLTRST#" → 释放 
"CPURST#" → CPU 从 
"0xFFFFFFF0" 取指
这一长串跑完，才算"供电稳定"，POST 才真正开始。

要不要接着拆 
"0xFFFFFFF0" 那条复位向量到底指向 SPI Flash 的哪个地方，或者 SEC 阶段 
"Cache-As-RAM" 那个 trick 具体怎么玩的？前者偏"CPU 视角进固件"，后者偏"固件怎么在 DRAM 起来之前活下来"。
